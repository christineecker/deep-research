# ReadCube compatibility trial fixture (Phase 2.1)

A ready-to-import bundle for the manual verification step in
`REFERENCE_MANAGER_V2_PLAN.md`'s "2.1 — ReadCube compatibility trial". Everything here was
generated by the actual `export.py readcube` CLI (not hand-written) against a small
`refmgr` fixture library, so it exercises the real code path.

**Bundle to import**: `bundle-dest/compat-trial-<id>/` — the batch directory containing
`references.ris`, `references.bib`, `PDFs/`, `Supplements/`, `manifest.json`,
`import-report.md`, `README.md`, `COMPLETE.json`. All four PDFs are small but genuinely
valid, text-extractable PDFs (verified with `pdftotext`) — not placeholder bytes — so
ReadCube's reader has real single-page content to open.

## What it contains (7 references, covering the plan's required trial cases)

1. **Full metadata + DOI + PMID + primary PDF** — "A Fully Described Reference for
   ReadCube Import". Checks RIS field preservation (volume/issue/pages/abstract/PMID
   `AN` tag) and PDF matching.
2. **Metadata-only, no PDF** — "A Metadata-Only Reference With No Attachment".
3. **No DOI/PMID/PMCID at all** — "A Reference With No DOI, PMID, or PMCID".
4. **Unicode title/authors** — two references: one metadata-only
   ("Über die Grundlagen — β-Analyse..."), one with a PDF attached
   ("Zweite Unicode-Referenz mit PDF-Anhang").
5. **A reference with a supplement** — "A Reference With a Supplementary File" (primary
   PDF in `PDFs/`, a second file in `Supplements/`).
6. **A reference with two PDF versions** — "A Reference With a Preprint and a Published
   Version" (published copy in `PDFs/`, preprint copy in `Supplements/`).

## What to check manually in the ReadCube desktop app (per the plan's 2.1 acceptance list)

- Import `references.ris` (and separately try `references.bib` in a second attempt, if
  useful for comparison — the plan says tell users to pick one, not both, in real usage;
  this trial is the one place both are worth checking).
- RIS field preservation and reference-type handling (all imported as `JOUR`/`GEN` per
  the RIS `TY` tags above).
- PDF matching after metadata import (import the `PDFs/` files next, per `README.md`
  inside the bundle).
- Supplement/version handling: does ReadCube associate `Supplements/*.pdf` with the
  right reference automatically, or does it need manual attachment? (The plan explicitly
  says: "Do not promise attachment association through RIS file-path fields without
  testing support in the current ReadCube app" — this is exactly that test.)
- Repeated identical import (import the same `references.ris` twice) and changed-metadata
  behavior (edit one field, re-import) — does ReadCube dedupe, duplicate, or merge?
- Citation key / notes / keyword transfer, if you want to assess importing `manifest.json`
  citation keys as ReadCube tags/keys (not automated by this bundle — RIS carries no
  citation-key field by convention).
- Figure/page viewing: open one imported PDF in ReadCube's reader and confirm the page
  renders (it will show a short text label, e.g. "Deep Research Compatibility Trial -
  Primary" — that's the fixture's content, not a real paper).

Record the ReadCube app version and what you observe — the plan's 2.1 acceptance is
"labeled integration unverified until this trial passes," so whatever you find (including
"doesn't associate supplements automatically") is a valid, useful result, not a blocker to
fix here.

## Regenerating this fixture

The library and bundle here are build artifacts, not hand-edited — to regenerate after an
`export.py`/`ris.py` change, rebuild the `library/` fixture (see the paper-construction
script in this task's session, or write a fresh one following the same 7-record shape)
and re-run:

```bash
python3 skills/deep-research/scripts/export.py readcube \
  --repo references/fixtures/compat-trial/repo --source refmgr \
  --library references/fixtures/compat-trial/library \
  --all --destination references/fixtures/compat-trial/bundle-dest \
  --name compat-trial --bib
```
