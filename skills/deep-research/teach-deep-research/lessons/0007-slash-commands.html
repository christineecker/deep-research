Lesson 7 of the deep-research course

You don't always need the pipeline

The repo became a Claude Code plugin. Along with that came 11 /deep-research:* slash commands — each one calls a script directly, no Stage 0–8 negotiation. This lesson is about knowing when to reach for one instead of asking for "a literature review."

The shape of the decision

AskRoute
"Register these five papers, I'll search/filter/export later"/deep-research:pool-add
"Summarize this one paper"/deep-research:summarize
"Summarize this bounded set / topic scan"/deep-research:summarize-set
"Is this paper already in the pool?"/deep-research:pdf-lookup
"Export my registry as BibTeX"/deep-research:bib-export
"How's my run doing / what's left?"/deep-research:status, /deep-research:watch
"Do these outputs check out?"/deep-research:verify
"Set up a manuscript folder"/deep-research:project
"Literature review / what does the evidence say about X"Full pipeline — not a command

Every command name above is a script name in disguise — pool-add is library.py pool-add, summarize/summarize-set are paper.py, status/verify/watch are their own scripts. The command spec's job is just to parse $ARGUMENTS and print the exact invocation before running it — nothing about the pipeline narrative in SKILL.md is read for these.

pool-add vs. summarize-set — the one mixup worth avoiding

Both take a set of papers. The difference is whether you want content yet.

  • pool-add: bibliographic record only. No reading, no summary, no appraisal. Cheap, fast, just gets papers onto the shelf.
  • summarize-set: full read + summarize (optionally appraise) per paper. Not sure which papers would even be picked from a topic scan? Add --select-only to stop after the candidate list, before paying for any summaries — then re-run without it once the set looks right.

One prerequisite, one exception set

Every command except status, verify, and watch takes --repo <path> and fails without a data/papers/registry.jsonl already there — run /deep-research:init <path> once first (or --from-wiki <wiki-root> to import from an existing wiki-manager wiki instead of starting empty). status/verify/watch key off --run-dir instead, which only exists once a full pipeline run has started — they read an existing run, they don't need a repo of their own.

Why this doesn't replace Lesson 6

Lesson 6's paper.py summarize/summarize-set profiles are what these slash commands wrap for the summary asks. The slash-command layer changed how you invoke that profile (a one-line command instead of remembering the script path and flags) — it didn't change what the profile does, its "not a meta-analysis" invariant, or its shared-pool reuse with the full pipeline.

Check yourself

You want to know which papers a run is still waiting on full text for. Which command?

You want a candidate list from a topic scan, but don't want to pay for summaries yet. Which flag, on which command?

A colleague asks "what does the evidence say about X" — a real multi-paper question. Route it to a slash command?
