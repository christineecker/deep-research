Lesson 1 of the deep-research course

What is deep-research, and when do I reach for it?

Before touching any stage mechanics: what this tool is, what it refuses to be, and the one sentence that should make you say "yes, use deep-research."

What it does

deep-research is a Claude Code skill that runs a full PubMed-centred literature research pipeline, end to end: protocol → search → screen → full-text acquisition → extraction → appraisal → synthesis → verified report, optionally promoted into a wiki. You (the coordinator, "main thread") configure the run and write the synthesis; scripts do network/state work; subagents do per-paper screening, extraction, and appraisal.

What it is not

  • Not a meta-analysis. No pooled effects, no I², no forest plots — synthesis is effect-direction tabulation plus explained conflict.
  • Not a paywall bypass. No credentials, no proxies, no scraping around access. Unobtainable text is quarantined and handed back to you, never faked.
  • Not the full pipeline for a single paper. Summarizing one PDF, one PMID, or a small user-supplied set doesn't need Stage 0–8 at all — a separate lightweight profile handles that case (see Lesson 6).

The trigger phrase

It fires on requests shaped like: "literature review," "systematic review," "evidence synthesis," "what does the evidence say about X," "deep research on X," "PubMed search," "critical appraisal," or "screen/extract/appraise these papers with citations."

Rule of thumb: if the honest answer requires reading several papers and weighing them against each other, it's a deep-research job. If it requires reading one paper, it isn't.

The one thing every run needs before it starts

Stage 0 always asks the same handful of setup questions — it never guesses a profile or a target from how the question "sounds." The two decisions worth knowing cold:

1. Profile — how thorough?

ProfileFor
fastQuick read of the field. 10 articles, no gates.
standard (default)The normal case. 25 articles.
systematicDefensible review — dual screening, PRISMA log. 60 articles.
maxWidest sweep — + guidelines/grey-lit/web. 100 articles.

Full stage-by-stage table: Pipeline Cheat Sheet.

2. Target — wiki or standalone repo?

Where the run, the PDF/paper store, and the cross-run shared pool live. Wiki mode is the default — needs a wiki-manager wiki. Standalone repo mode needs no wiki at all and is the right pick when the deliverable is a manuscript project, not a wiki page.

The tangible win for this lesson: given any research request, you can now say in one breath whether it's a deep-research job, and if so, which profile you'd start with and why — before the tool has asked you anything.
