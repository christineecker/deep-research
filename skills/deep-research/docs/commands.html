Slash commands

Use the slash commands for the everyday cases; drop to the raw scripts for everything they don't cover.

Each /deep-research:* command calls one script directly, with no Stage 0-8 negotiation, and prints that script's own JSON. There are deliberately fewer wrappers than scripts — where no wrapper exists, the script call is given below rather than hidden.

How These Commands Behave

Three conventions hold across every script in the skill. Knowing them is worth more than memorizing flags.

ConventionDetail
Everything prints JSONEvery command emits a single object with schema_version, status (ok / error), command, and its payload. An error carries a human-readable error string, quoted rather than paraphrased.
status drives the loopScripts never call a model. Where model work is needed they return pending_retrieval, pending_extraction, pending_appraisal, or pending_summary. The agent dispatches that subagent, the subagent writes its file, the same command is re-run, and the script resumes. completed ends the loop.
Re-running is the interfaceNot a retry hack. Completed work is not redone: a satisfied ladder rung is never re-attempted, a promoted extraction is immutable unless its inputs_hash changes, and an unchanged snapshot is skipped rather than re-split.
 
$ python3 scripts/registry.py doctor --repo ~/lit/
{
  "schema_version": 1,
  "status": "error",
  "command": "doctor",
  "error": "no refmgr library at ~/lit/data/refmgr — nothing to check; `registry.py reindex` creates one"
}

Exit codes matter for the ones you might cron: doctor exits non-zero only for actual data loss — missing or corrupt assets, dangling attachments — while stale index rows are reported but stay "healthy", because reindex fixes those and nothing is at risk.

Full-Text Acquisition

No wrapper — Stage 4 plumbing, but worth knowing by hand when a run stalls on a ladder handoff (Stage 4):

python3 scripts/fulltext.py acquire --corpus <corpus.jsonl> --run-dir <run> \
    [--only-pmid X] [--from-tier N] [--email addr] [--offline] [--no-ocr] [--workers N]
python3 scripts/fulltext.py status --run-dir <run>
python3 scripts/fulltext.py resolve-mcp     --run-dir <run> --evidence-id <id> (--text-file <p> | --status unavailable)
python3 scripts/fulltext.py resolve-browser --run-dir <run> --evidence-id <id> (--text-file <p> [--institutional] | --status unavailable)

python3 scripts/library.py ingest-inbox --run-dir <run> --wiki <root> [--no-apply]
python3 scripts/library.py lookup --wiki <root> (--doi|--pmid|--pmcid|--title|--sha256)

--from-tier N discards rung state at or above N and walks again from there; --offline marks network rungs skipped rather than failed, so a later online pass still tries them.

/deep-research:annotate rate --repo <path> --evidence-id pmid:38214501 --stars 4
/deep-research:annotate note --repo <path> --evidence-id pmid:38214501 --set "..."
/deep-research:annotate list --repo <path> --tag to-read --min-rating 3
/deep-research:embed index   --repo <path>
/deep-research:embed similar --repo <path> --evidence-id pmid:38214501 --k 5
/deep-research:embed query   --repo <path> --text "does X reduce Y?" --k 10
/deep-research:ask --repo <path> "does exercise reduce depressive symptoms in adolescents?"
/deep-research:alerts save --repo <path> --name cbt --query "CBT AND adolescents"
/deep-research:alerts run  --repo <path> --register
/deep-research:reindex --repo <path>
/deep-research:doctor  --repo <path> --deep
/deep-research:okf-export --repo <path> --evidence-id pmid:38214501 --wiki <wiki-root>

embed index and embed query require the optional third-party package sentence-transformers — the one scoped exception to the skill's no-pip-installs policy; ask runs without it, on lexical retrieval alone. ask answers only from spans that verify against the snapshot store, and only from papers the repo already holds — it is not a literature search. okf-export requires each --evidence-id to already have an extraction on file. Details: Reference manager.

ReadCube Export

/deep-research:export --repo <path> --all --destination <folder> --require-pdfs
/deep-research:export --repo <path> --evidence-id pmid:38214501 --destination <folder> --incremental
/deep-research:export --repo <path> --run-dir <run> --destination <folder> --bib --dry-run

Distinct from okf-export: this publishes a local RIS + PDF bundle for the ReadCube desktop app, not an OKF wiki bundle — it never touches wiki state and needs no extraction on file. Add --source refmgr --library <path> to read from the newer SQLite reference-manager layer instead of the registry (supports multiple attachments per paper; --all/ --evidence-id selection only, not --run-dir). Details: ReadCube export.

Run Monitoring

/deep-research:status <run> --table
/deep-research:status <run> --missing
/deep-research:watch --run-dir <run> --once

And the task board and no-progress guard, which have no wrappers:

python3 scripts/corpus.py task list --run-dir <run> --stage extract
python3 scripts/corpus.py guard --run-dir <run> --no-record    # status check, records nothing
python3 scripts/corpus.py prisma --run-dir <run>

Use --no-record when polling: every recording call appends a probe, so repeatedly checking a legitimately parked run manufactures the flat window the guard looks for.
