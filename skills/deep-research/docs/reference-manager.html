Standalone repo, extended

The standalone repo doubles as a personal reference manager: search, tag, rate, and export what you've registered.

Registering and reading papers already worked. This adds faceted/keyword/semantic search over the registry, personal tags/star-ratings/notes, and a bridge from a hand-picked paper set into an OKF knowledge-graph bundle — all on top of the same data/papers/ store, with no new skill and no changes to the wiki-backed review pipeline.

Looking for ReadCube? This page covers the registry's own search/tag/rate/OKF-export layer. Publishing a bundle for the ReadCube desktop app — the actual library/PDF-viewing UI — is a separate, newer feature: ReadCube export.

Search (registry.py search)

One subcommand, three layers, all combinable in a single call:

  • Facet filters — --journal, --year, --status, --extraction-status, --appraisal-status — plain in-memory filters over fields the registry already carries.
  • Annotation filters — --tag, --min-rating — join read-only against annotations.jsonl.
  • Keyword search — --q "text" — a stdlib-only, lowercase AND-of-terms match over title, abstract, journal, the extraction's claim sentences and outcome names, extraction narrative, appraisal rationale (scope it to one review with --project), and the paper's full text. Claims are searched ahead of raw full text, so a snippet quotes the extracted finding whenever both match.
  • Similarity ranking — --similar-to <evidence-id> — re-ranks whatever the filters above surfaced by cosine similarity, using the cache built by embeddings.py index.
python3 scripts/registry.py search --repo ~/lit/ --tag to-read --min-rating 4 --q "biomarker"

Annotations (annotations.py)

Tags, a 1-5 star rating, and a free-text note per paper — your own opinion, kept out of the canonical registry and out of project-scoped appraisal on purpose, the same way appraisal already stays separate from the registry. An annotation never requires the paper to be registered first.

python3 scripts/annotations.py tag  --repo ~/lit/ --evidence-id pmid:38214501 --add to-read
python3 scripts/annotations.py rate --repo ~/lit/ --evidence-id pmid:38214501 --stars 4
python3 scripts/annotations.py note --repo ~/lit/ --evidence-id pmid:38214501 --set "Good discussion of threshold selection."
python3 scripts/annotations.py show --repo ~/lit/ --evidence-id pmid:38214501
python3 scripts/annotations.py list --repo ~/lit/ --tag to-read --min-rating 3

Semantic Similarity (embeddings.py)

Build a cached embedding per paper from its title, abstract, and extraction narrative, then ask for nearest neighbors by cosine similarity, in pure Python — no re-embedding at query time. similar starts from a paper you already have; query starts from a question. Neither ranks across two embedding models — query says so and stops rather than mixing them.

python3 scripts/embeddings.py index   --repo ~/lit/
python3 scripts/embeddings.py similar --repo ~/lit/ --evidence-id pmid:38214501 --k 5
python3 scripts/embeddings.py query   --repo ~/lit/ --text "does X reduce Y in older adults?" --k 10

# or fold similarity into a faceted/keyword search once the index exists:
python3 scripts/registry.py search --repo ~/lit/ --similar-to pmid:38214501 --limit 5
Scoped pip-install exception. embeddings.py index requires the third-party package sentence-transformers (pip install sentence-transformers, default model all-MiniLM-L6-v2), imported lazily inside the one function that needs it. This is the one deliberate, narrow exception to deep-research's blanket "zero pip installs, ever" policy — scoped to this single script only. Nothing else in the skill needs any pip install: full-text acquisition, extraction, appraisal, and everything else stay stdlib-plus-requests/pdfminer as before, and embeddings.py similar/registry.py search --similar-to never need the package once embeddings.jsonl already exists.

OKF Knowledge-Graph Export (research.py okf-export)

Pick N papers out of the registry by evidence_id and promote them into an existing OKF wiki bundle, reusing okf.py promote's validator unmodified rather than hand-writing a second concept-emission path. Each evidence_id must already have an extraction on file (run /deep-research:summarize first if not).

python3 scripts/research.py okf-export --repo ~/lit/ \
  --evidence-id pmid:38214501 --evidence-id doi:10.1001/jama.2023.24567 \
  --wiki ~/wiki/ --project diagnostics-review
Concepts land as provisional, not stable. okf-export synthesizes a throwaway run directory and runs the existing verify.py/okf.py promote over it unmodified. A registry-only selection has no real search log or PRISMA screening history behind it, so pipeline-completeness checks like C-SEARCH-LOG and C-PRISMA are expected to fail — that's why okf-export calls okf.py promote with --force --allow-unverified, and every concept it writes comes out status: provisional. Concept-level correctness (the full V1-V25 validator) is still enforced, unforced.

End-To-End Example

$ python3 scripts/research.py init ~/lit/
{"status": "ok", "command": "init", "repo_root": "/home/you/lit"}

$ python3 scripts/registry.py add --repo ~/lit/ --pmid 38214501
{"status": "ok", "evidence_id": "pmid:38214501", ...}

$ python3 scripts/registry.py add --repo ~/lit/ --doi 10.1001/jama.2023.24567
{"status": "ok", "evidence_id": "doi:10.1001/jama.2023.24567", ...}

$ python3 scripts/registry.py add-pdf --repo ~/lit/ --file ~/Downloads/smith2024.pdf
{"status": "ok", "evidence_id": "pmid:39012233", ...}

$ python3 scripts/annotations.py tag  --repo ~/lit/ --evidence-id pmid:38214501 --add diagnostics
$ python3 scripts/annotations.py tag  --repo ~/lit/ --evidence-id pmid:38214501 --add to-read
$ python3 scripts/annotations.py rate --repo ~/lit/ --evidence-id pmid:38214501 --stars 5
$ python3 scripts/annotations.py note --repo ~/lit/ --evidence-id doi:10.1001/jama.2023.24567 \
    --set "Good external validation cohort."

$ python3 scripts/registry.py search --repo ~/lit/ --journal "JAMA" --min-rating 3
{"status": "ok", "results": [ ... ]}

$ python3 scripts/registry.py search --repo ~/lit/ --q "biomarker threshold" --tag diagnostics
{"status": "ok", "results": [ ... ]}

$ python3 scripts/embeddings.py index --repo ~/lit/
{"status": "ok", "command": "index", "embedded": 3, "skipped_current": 0}

$ python3 scripts/embeddings.py similar --repo ~/lit/ --evidence-id pmid:38214501 --k 5
{"status": "ok", "results": [
  {"evidence_id": "pmid:39012233", "title": "...", "score": 0.81},
  {"evidence_id": "doi:10.1001/jama.2023.24567", "title": "...", "score": 0.74}
]}

$ python3 scripts/paper.py summarize --repo ~/lit/ --pmid 38214501
{"status": "ok", ...}   # needed before okf-export: it requires an extraction on disk

$ python3 scripts/research.py okf-export --repo ~/lit/ \
    --evidence-id pmid:38214501 --wiki ~/wiki/
{"status": "ok", "command": "okf-export", "promote_exit_code": 0, ...}
