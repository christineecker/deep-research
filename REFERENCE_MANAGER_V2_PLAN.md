# Reference manager v2 — plan (backlog)

This document is a forward-looking backlog, not a build log. Completed work
is described only briefly, with pointers to the actual code/tests as the
source of truth — read those, not this file, for how something works.
Historical design rationale that's no longer load-bearing has been dropped;
`REFERENCE_MANAGER_V2_ADR.md` has been folded in here and removed.

## What this project is

A reliable local SQLite backend for papers, identifiers, assets,
attachments, organization, and citations — serving deep-research's own
automation (dedup, evidence-linking, citation keys, search) — plus a
`/deep-research:export readcube` command that prepares ReadCube-compatible
import bundles (RIS + PDFs) on request. **ReadCube itself is the human
library UI and PDF/figure viewer; this project does not build or maintain
either.** A custom browser library table, an embedded PDF reader, in-app
highlight/figure-capture UI, and any local HTTP service exposing them are
permanently out of scope, not just deferred. If a narrow agent-driven need
for page/figure inspection ever arises, it should be a CLI/script
capability against the existing poppler/tesseract tooling — not a browser
feature.

## What exists today

- **`skills/deep-research/scripts/refmgr/`** — SQLite storage/service
  layer: migrations (`db.py`, WAL, `BEGIN IMMEDIATE` transactions),
  `identity.py` (ID generation, DOI/PMID/PMCID/URL normalization),
  `repositories/` (papers, identifiers, assets, attachments, organization,
  audit, merges — atomic compound operations — search, saved_searches),
  `service.py` (facade: idempotent import, auto-reindexing, proven under
  real multi-process concurrency). **Not wired to any CLI command** — see
  "Open decisions" below.
- **`skills/deep-research/scripts/export.py`** (`readcube` subcommand) +
  `export_select.py`, `export_select_refmgr.py`, `ris.py`,
  `export_ledger.py` — selection, two `AssetSource` implementations
  (`--source legacy|refmgr`), RIS/BibTeX serialization, staged atomic
  publish (`PDFs/` + `Supplements/`), incremental export ledger. Docs:
  `commands/export.md`, `references/readcube-export.md`,
  `references/schema/17-export-manifest.md`.
- **Search**: `refmgr/repositories/search.py` (FTS5 lexical search over
  paper title/authors/journal/abstract/identifiers, filters, keyset
  pagination, coverage reporting) and `saved_searches.py`, wired into
  `service.py` as `.search`/`.saved_searches`.
- **Compatibility-trial fixture** for the one remaining manual Phase 2
  step: `skills/deep-research/references/fixtures/compat-trial/` — a real
  bundle generated by the actual CLI, with a README walking through what
  to check in the ReadCube desktop app.

All of the above is untracked/uncommitted on branch `refmgr-v2/phase0`, has
its own test suite (`skills/deep-research/tests/test_refmgr*.py`,
`test_export*.py`, `test_ris.py`), and is not further described here.

The pre-existing, separately-shipped JSONL prototype
(`annotations.py`/`embeddings.py`/`registry.py search`/`research.py
okf-export` and their commands) is real, tested, documented, user-facing
functionality — untouched by this plan and not being removed. It predates
and is independent of the `refmgr` work above; see "Known issues and
standing decisions" for its specific gaps relative to the `refmgr` data
model.

## Data model and invariants

Implemented entities: Paper, Identifier, Asset, Attachment, Organization,
Audit/merge — immutable IDs, identifier normalization with alias
retention, content-addressed dedup, attachments never overwritten,
original PDFs immutable, visible diagnostics over silent failure. Search
(FTS5) is a rebuildable derived index, never a source of truth.

Deferred, open question (see "Open decisions"): Page-derivative,
Annotation, and Job entities. Embedding stays relevant independent of
that question (semantic search/dedup, not a browser UI) — see "Remaining
work" below.

## Known issues and standing decisions

- **Interpreter**: target the uv-managed 3.11.15 environment (what `pip`
  resolves to on this machine), not whichever `python3` happens to be on
  PATH — the existing `sentence-transformers` carve-out already assumes
  this.
- **Storage**: SQLite (stdlib) + FTS5 — confirmed available, no install
  needed, WAL-safe on this filesystem.
- **PDF/OCR**: `pdftoppm`/`pdftotext`/`tesseract` CLI tools are available
  and sufficient for now; only add `pymupdf`/`pdf2image`/`pytesseract`
  Python bindings when a concrete task needs in-process page access that
  shelling out can't do cleanly — don't install them speculatively.
- **Dependency policy**: core deep-research skill scripts remain
  stdlib-only. `sentence-transformers` is the one existing, documented
  exception (`references/acquisition.md`). No FastAPI/uvicorn or frontend
  build tooling is needed — the browser-app direction that would have
  required them is retired.
- **Known defect, not yet fixed**: `registry.py`'s `Registry.__init__`
  calls `self._load()` before any call site acquires `advisory_lock`, at
  every mutating call site (`cmd_add`, `cmd_add_pdf`, `cmd_import_bib`,
  `cmd_import_folder`, `cmd_pool`, plus `pool.py`/`paper.py`/`research.py`
  equivalents) — a real read-modify-write race where concurrent writers
  can silently clobber each other's changes. Tracked under "Remaining
  work" below; the `refmgr` layer's own `db.transaction` does not have
  this bug (verified under real concurrent-process load).
- **Disposition of the JSONL prototype**: `annotations.py`'s Annotation
  model is paper-level only (tags/rating/note) — no attachment anchoring,
  bounding boxes, or revision history. `embeddings.py`'s Embedding model
  has no chunk granularity, input hash, or processor version — can't
  safely detect staleness or mixed-model comparisons. `research.py
  okf-export`'s `--force --allow-unverified` pattern is a known mechanism
  to revise (see "Remaining work," Phase 5). None of this is being
  deleted or rewritten now — it's real working code — but none of it
  should be treated as a model to extend when building the items below.

## Remaining work

### Phase 2 close-out (manual, needs the user)

- **ReadCube compatibility trial**: import
  `skills/deep-research/references/fixtures/compat-trial/bundle-dest/compat-trial-*/`
  into the real ReadCube desktop app and work through that directory's
  README (RIS field preservation, PDF matching, supplement/version
  association, repeated-import behavior, figure viewing). Record the app
  version and what you observe.
- **iCloud destination acceptance**: once given a real destination folder,
  publish a real batch there and verify against the compatibility trial's
  findings.

### Phase 4 remainder — search and large-library processing

- Replace `embeddings.py`'s model-name-only freshness check with real
  input hashes and full configuration fingerprints (model + dimension +
  normalization + processor version); add chunk-level granularity
  (currently one vector per whole paper). Independently large,
  model/chunking design work.
- Benchmark exact semantic retrieval before choosing an
  approximate-nearest-neighbor dependency (depends on the above).
- Attachment/processing filters and any filter needing page-level text —
  blocked on the Page-derivative/Annotation entity decision below.
- Bounded workers for text extraction/OCR/rendering/indexing with
  cancellation/retry/restart-recovery — not urgent while ReadCube, not
  this project, does PDF reading.
- 10k/100k-record lexical-search latency benchmark
  (`references/reference-manager-benchmark-fixtures.md`) — needs real
  bulk data in `refmgr`, which needs the CLI cutover decision below.

### Phase 5 — citations and research integration

- Route research acquisition into the shared `refmgr` attachment pool once
  the CLI cutover happens; connect extractions to exact
  attachment/snapshot versions.
- Distinguish personal annotations from verified research claims, and
  display abstract-only/full-text status clearly, in `import-report.md`
  and paper-summary output.
- Revise `research.py okf-export`'s `--force --allow-unverified` pattern:
  introduce a reference-selection export validation mode that exempts
  absent search/PRISMA history explicitly while retaining checks for
  evidence identity, spans, and source consistency — remove blanket
  forcing as the normal mechanism. Independent of the CLI cutover; can be
  done anytime.

(Citation-key collision handling is already implemented and tested in
`refmgr`'s `PaperRepository.set_citation_key` — nothing left to do there.)

### Phase 6 — recovery, release, and scale hardening

Not started; full original scope (SQLite backup with asset
manifest/checksums, restore into a separate directory, health checks,
missing-file/orphan detection, retention/cleanup controls, bounded
caches/workers, a documented acceptance walkthrough). Not urgent while
`refmgr` holds no real user data.

## Open decisions

1. **CLI cutover timing**: when (or whether) to route `registry.py
   add/import/lookup` through `refmgr`'s service layer. Not required for
   anything currently buildable — the export command targets the legacy
   registry directly and `RefmgrAssetSource` only needs `refmgr` data to
   exist, not `registry.py` writing to it.
2. **Whether Page-derivative/Annotation/Job entities are still needed at
   all**, now that ReadCube owns PDF viewing/annotation. Recommendation:
   don't build them speculatively — revisit only if a concrete
   agent-driven use case requires it, and scope it as a narrow CLI
   capability, not a UI feature, per "What this project is" above.
3. Backup destination remains user-configured, no cloud sync — otherwise
   unchanged from earlier defaults.
