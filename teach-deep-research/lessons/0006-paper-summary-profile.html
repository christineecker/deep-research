Lesson 6 of the deep-research course

When the ask is one paper (or a handful), not a review

Lesson 1 drew the line: full pipeline is for multi-paper synthesis. This lesson covers what's now on the other side of that line — scripts/paper.py's two lightweight profiles, added after the earlier lessons were written.

Two commands, two shapes of ask

AskCommand
"Summarize this paper" — one PMID/DOI/PMCID/PDFpaper.py summarize
"Summarize these three papers," a user-supplied set, or a bounded topic/question scanpaper.py summarize-set
"Literature review," "what does the evidence say about X"Full pipeline (SKILL.md) — never these profiles

Both profiles reuse the standalone-repo pool (registry, extractions, appraisals) instead of running Stage 0–8. If a paper was already extracted or appraised in a full review, a summary of it reuses that work instead of redoing it — and the reverse holds too: a paper summarized standalone today feeds a full review later without re-extraction.

What a summary is not

No PRISMA flow. No effect-direction synthesis across papers. No GRADE table. No meta-analysis. verify.py hard-fails a summary that contains cross-study, pooled, or consensus wording — that vocabulary belongs to the full pipeline only.

The single-paper workflow

Same shape as Stage 5/6 of the full pipeline, just for one paper: registry lookup/registration → acquisition (same ladder) → extraction (reuse or new, one subagent) → appraisal (reuse or new, on by default for fulltext) → summary assembly (one subagent, schema §14) → verify.py single-paper-summary → export. The CLI never dispatches a subagent itself — same rule as everywhere else in this skill: it reports a status (pending_extraction, pending_appraisal, pending_summary, completed) and the orchestrating agent (you) decides what to run next.

The selected-paper workflow

Runs the single-paper path once per identifier, with partial failures recorded rather than fatal (failed_identifiers, schema §15). Two entry modes:

  • Explicit — you already know the papers: --pmid (repeatable), --ids-file, --bib, or --folder --recursive.
  • Question/topic — a bounded search produces the candidate list (--question or --topic, capped by --limit or a hard default). The query, database, timestamp, and limit are all recorded in selection_basis. --select-only stops after the candidate list, before any summarizing runs.

Optional --overview adds a bounded cross-paper orientation section — but only from already-verified §14 descriptive fields (design, population, intervention, outcomes measured). It still never infers a pooled effect, a certainty rating, or a consensus. That restraint is the same invariant as the "not a meta-analysis" line from Lesson 1, just enforced one layer down.
