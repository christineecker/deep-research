Lesson 2 of the deep-research course

Stage 0: what the pipeline actually asks you

Lesson 1 gave you the profile/target shorthand. This lesson is the real Stage 0 conversation — the five things it needs from you, in the order it needs them, so a live run never catches you flat-footed.

The rule Stage 0 follows

It asks only for what it doesn't already know, and never re-asks what's already sitting in the run's config.json. That means: on a first run, expect all five; on a resumed or templated run, expect fewer.

1. Question — restated through a framework

Before anything runs, your question gets rephrased into a formal framework and shown back to you. The skill doesn't default blindly to PICO — it picks the framework that fits the question's shape:

Question shapeFramework
Intervention has a comparator (drug vs. placebo, therapy vs. usual care)PICO
Exposure/etiology, no intervention (does X cause Y)PECO
Population + exposure, no comparator neededPEO
Scoping review (map a concept, not answer a question)PCC
Qualitative or mixed-methodsSPIDER
Service delivery / implementationSPICE

Full definitions: references/question-frameworks.md. Your job here isn't to name the framework yourself — it's to check the restatement is right before the pipeline commits to it. A wrong Population or a missing Comparator at this step becomes wrong inclusion/exclusion criteria at Stage 1.

2. Profile — or its parts, individually

You already know fast/standard/systematic/max from Lesson 1 (full table: cheat sheet). What's new here: you don't have to accept a bundle. Stage 0 will take scope, gates (protocol confirmation, screening double-check), and max_articles as separate overrides, and everything is still editable afterward directly in the run's config.json.

One more lever worth knowing cold: pipeline.stop_after_stage. Set it to 5 and the run does search → screen → retrieve → extract, then halts — no appraisal, no report. That's the move for building up the shared paper pool on a topic before you've decided the topic deserves a full appraised review. Clear the field later and resume the same run to carry on into appraisal.

3. Target — wiki or standalone repo, and its setup command

Lesson 1 gave you the decision. Here's the command each side actually needs before Stage 0 can proceed:

Wiki modeStandalone repo mode
One-time setuppython3 scripts/library.py init --wiki <root>python3 scripts/research.py init <path>
Needs wiki-manager?YesNo, ever

If you picked standalone and later want a manuscript deliverable rather than just a pool, add one more command: research.py project create <slug> --repo <path>. Changed your mind after the fact? research.py export wiki copies a repo's pool and one project's bundle into a wiki (one-way courtesy copy). Going the other direction, pool.py migrate --from-wiki <wiki> --repo <path> pulls an existing wiki's pool into a new standalone repo.

4. Filters

Stage 0 also collects the boring-but-decisive scoping knobs, all optional, all worth stating up front rather than discovering mid-run: years, authors, journals, article types, species/age, language, and OA-only (open-access-only, which matters a lot for Stage 4's retrieval success rate).

5. Outputs

report.md is always produced. On top of that you can ask for HTML, a Quarto PDF/docx, or promotion into an OKF bundle (wiki mode only). Decide this now, not after Stage 8 — it doesn't block earlier stages, but naming it up front avoids a second pass through Stage 8's render step.

The tangible win for this lesson: given a real question, you can now answer all five Stage 0 prompts in one go — framework check, profile (or its parts), target plus its one-time setup command, filters, and outputs — without the pipeline having to walk you through them one at a time.
